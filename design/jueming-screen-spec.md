# 一味·决明：主界面稿

目标：保留现有“暗底、古药、微恐、仍有生命在发光”的视觉语言，把地图从主玩法降为导航器，让场景与文字成为叙事主体。

## 板块

### 1. 场景舞台

- 占主视区约 60%。
- 每个场景一张底图，可叠加雾、瞳光、落尘、雨痕等低成本 CSS 动效。
- 不显示玩家完整立绘，以第一人称探索感为主。
- 场景变化必须对应真实状态变化，避免纯装饰动画争夺注意力。

### 2. 左上角小地图

- 宽度为场景舞台的 20%–25%，默认半透明。
- 只画节点与连线，不再显示 9×9 地砖。
- 已到达节点实线，听说但未验证的节点虚线，神庙伪造的节点在识破后像墨迹一样洇开消失。
- 灵伴不显示为坐标，只用地图边缘的震纹表示粗略方向。

### 3. 场景正文

- 一次显示 60–140 字，最多三小段。
- 重要异常单独成行，不用彩色大字提示“这是线索”。
- 已读内容进入可折叠旅记，不持续堆在主界面。

### 4. 情境选项

- 每个节点 2–4 个，使用动词开头。
- 区分探索动作与移动动作，但视觉权重相同。
- 条件不足的选项不隐藏，显示玩家能理解的原因，例如“你尚未确认声音来自谁”。
- 原地等待是正式动作。

### 5. 灵伴侧栏

- 展示灵伴主动说出的内容，不把它的所有结构化感知直接摊给人类。
- 开发/单人代理模式可开启“感知笺”查看距离、变化与触感；真实双人模式默认关闭。
- 真灵伴与回声在样式上保持接近，判别依据来自行为与新信息。

### 6. 回合输入

- 玩家先选择情境动作，再写一句话；也允许不说话。
- “确认本回合”同时提交行动与话语。
- 结算时用一次短暂的灯灭动画遮住双方同步过程，不显示加载转圈。

## 移动端

- 顺序：场景舞台 → 场景正文 → 选项 → 对话。
- 小地图缩成舞台左上角可展开的圆形罗盘。
- 灵伴私有感知摘要不常驻，点灵伴名字展开。
- 主操作按钮距屏幕底部至少 20px，避免浏览器工具栏遮挡。

## 视觉继承

- 保留决明子插图的灰黑石质、旧金与银瞳。
- 银光代表“可验证但有限的信息”，金光代表“丰盛但可能被修饰的信息”。
- 危险不用鲜红；采用褪色朱砂，仅出现在玩家已经发现矛盾之后。
- 正文字号桌面 16–18px、移动端至少 16px，行高不低于 1.75，所有中文标题避免小于 1.15 的行高。

## 第一版验收

- 玩家进入后 10 秒内知道自己在哪里、能做什么、灵伴在哪里出现。
- 不看教程也能完成第一次场景选择。
- 玩家不会把小地图误认成主要操作区。
- 一次回合结算中，人类看不到灵伴未说出口的私有感知。
- 仅替换场景数据即可改变正文、选项和结果，无需修改界面组件。
